什么是MCP

2026年8月2日 · 2 分钟 · 288 字 · beyond

在 MCP 出现前，AI 模型只能“聊天”，无法直接操作外部世界（查数据库、发邮件、读文件等）。若想让 AI 连接 N 个工具和 M 个 AI 平台，理论上需写 N×M 套对接代码。MCP 统一了这套“接口标准”，开发者只需实现一次，即可被所有支持 MCP 的 AI 应用调用

MCP（Model Context Protocol，模型上下文协议）是 Anthropic 于 2024 年 11 月推出的开源协议，本质是为 AI 大模型与外部工具/数据源之间建立标准化连接的“通用接口”，被广泛类比为“AI 领域的 USB-C”。

核心架构（三个角色）#

MCP 采用 Host-Client-Server 三层架构：

  • Host（主机）：运行 AI 的应用，如 Claude Desktop、Cursor、VS Code Copilot，负责发起请求。
  • Client（客户端）：运行在主机内部，负责将 AI 指令翻译成标准协议消息，与服务端通信。
  • Server（服务器）：封装具体能力（如查天气、读数据库），对外暴露标准化工具供 AI 调用。

三大核心能力（原语）#

原语作用示例
Tools（工具）可执行的操作查天气、发邮件、创建 PR
Resources（资源）只读数据源文件、数据库记录
Prompts（提示模板）预定义的任务模板代码审查模板、周报模板

技术细节#

  • 通信协议：底层基于 JSON-RPC 2.0，所有消息均为标准 JSON 格式
  • 传输方式：支持 stdio（本地进程通信）和 Streamable HTTP（远程网络通信）两种模式
  • 治理归属：2025 年 12 月已移交至 Linux 基金会旗下的 Agentic AI Foundation（AAIF）管理，成为厂商中立的开放标准

通俗类比#

USB-C 出现前：手机、相机、打印机各有各的充电口，出门要带一堆线。 USB-C 出现后：一根线搞定所有设备。

MCP 出现前：每个 AI 对接每个工具都要单独写代码（3 个 AI × 5 个工具 = 15 套代码）。 MCP 出现后：AI 和工具都学会“MCP 这门普通话”，即插即用（3 + 5 = 8 个实现）。

MCP是一个http接口么?#

不完全是。MCP 是一个应用层协议，HTTP 只是它可选的传输方式之一。

准确地说，MCP 和 HTTP 的关系类似于 HTTP 和 TCP 的关系——MCP 运行在 HTTP 之上（也可以运行在别的东西之上），它本身不是 HTTP 接口。

为什么不能简单等同于 HTTP 接口？#

传输方式不止 HTTP 一种#

MCP 支持两种传输方式，HTTP 只是其中之一：

传输方式场景是否走网络
stdio（标准输入输出）本地开发、单机部署❌ 不走网络，通过进程管道通信
Streamable HTTP远程部署、云端服务✅ 走 HTTP 网络

用 stdio 模式时，MCP 完全不涉及 HTTP，它通过操作系统的 stdin/stdout 管道在进程间传递 JSON-RPC 消息。所以 MCP ≠ HTTP 接口。

消息格式不是 RESTful API#

传统 HTTP 接口是 RESTful 风格：不同的 URL + 不同的 HTTP Method（GET/POST/PUT/DELETE）。

MCP 的消息格式是 JSON-RPC 2.0，所有请求都发到同一个端点，通过 method 字段区分操作：

// 传统 RESTful API
GET /api/weather?city=北京

// MCP（JSON-RPC）
POST /mcp
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "get_weather",
    "arguments": { "city": "北京" }
  }
}

MCP 有传统 HTTP 接口不具备的能力#

能力传统 HTTP 接口MCP
工具自动发现❌ 需要读文档✅ tools/list 动态获取
双向通信❌ 单向请求-响应✅ 支持通知、进度推送
请求取消❌ 需自行实现✅ 协议原生支持
流式响应⚠️ 需额外实现✅ Streamable HTTP 原生支持

那为什么"感觉像 HTTP 接口"？#

因为在远程部署场景下，MCP 确实是跑在 HTTP 上的。你部署到服务器后，客户端通过一个 URL（如 https://mcp.yourdomain.com/mcp）连接，看起来就是一个 HTTP 服务。

更准确的理解是：

MCP = 应用层协议（定义"说什么"）+ 传输层（定义"怎么传"）

  • “说什么”：JSON-RPC 2.0 格式的工具发现、调用、资源访问
  • “怎么传”：可以是 HTTP，也可以是 stdio 管道

一句话总结#

MCP 就是给 AI 装了一个“万能插头”，让它从“只能聊天的天才大脑”变成“能连接万物、操作万物的数字助理”。MCP 不是 HTTP 接口，而是运行在 HTTP（或 stdio）之上的应用层协议。HTTP 只是它的"交通工具"之一，MCP 真正定义的是 AI 与外部工具之间"怎么对话"的标准。

就像 HTTP 不是 TCP——HTTP 用 TCP 传输，但 HTTP 本身是一套更高层的语义规范。MCP 和 HTTP 的关系也是如此。
