如何在github搭建个人主页

2026年7月5日 · 2 分钟 · 372 字 · beyond

作为一个开发者，经常在github逛的时候，发现好多以github.io结尾的站点，这个是不是很酷？不需要自己的服务器，就能发布，本文详细记录了这个过程

用 GitHub 搭建个人站点，核心都是基于 GitHub Pages 这个免费静态网站托管服务，区别在于你用什么工具来生成网站内容。主要有以下几种方式：

方式一：纯手写 HTML（最简单）#

直接在仓库里放 index.html 文件，GitHub Pages 会自动托管。

  • 适合：有前端基础、只需要简单展示页的人
  • 优点：零依赖，零配置
  • 缺点：内容多了维护困难，没有博客功能

方式二：Jekyll（GitHub 官方推荐）#

Jekyll 是 GitHub Pages 原生支持的静态站点生成器，推送到仓库后 GitHub 会自动构建，无需额外配置 CI/CD。

  • 适合：想快速上手、不想折腾构建流程的人
  • 优点：与 GitHub Pages 无缝集成，主题丰富（Jekyll Themes）
  • 缺点：依赖 Ruby 环境，本地开发需要安装 Ruby 和 Bundler
  • 典型用法：创建 <用户名>.github.io 仓库，配置 _config.yml，在 _posts 文件夹写 Markdown 文章

方式三：Hugo（你目前在用的）#

Hugo 由 Go 语言编写，构建速度极快，单二进制文件，无需复杂环境。

  • 适合：追求构建速度、喜欢灵活配置的人
  • 优点：构建速度最快（几百篇文章只需几百毫秒），主题生态丰富，安装简单
  • 缺点：GitHub Pages 不原生支持，需要通过 GitHub Actions 手动构建部署
  • 典型用法：本地 hugo 命令生成静态文件，通过 Actions 推送到 Pages 仓库

方式四：Hexo#

Hexo 基于 Node.js，是国内非常流行的博客框架，中文社区活跃。

  • 适合：熟悉 Node.js 生态、喜欢中文社区资源的人
  • 优点：中文文档丰富，插件多，部署命令简单（hexo d）
  • 缺点：依赖 Node.js 环境，同样需要通过 Actions 或 hexo-deployer-git 插件部署
  • 典型用法：hexo init 初始化 → hexo new 写文章 → hexo g && hexo d 部署

方式五：其他静态生成器（VitePress、Docusaurus、Astro 等）#

这些工具更偏向文档站或现代前端框架风格。

  • 适合：有前端开发经验、想做技术文档站或个性化站点的人
  • 优点：功能强大，组件化开发
  • 缺点：学习成本较高，需要配置 Actions 构建部署

对比总结#

方式构建工具部署方式上手难度构建速度
纯 HTML无直接推送⭐—
JekyllRubyGitHub 自动构建⭐⭐中等
HugoGoGitHub Actions⭐⭐⭐极快
HexoNode.js插件/Actions⭐⭐⭐快
VitePress 等Node.jsGitHub Actions⭐⭐⭐⭐快

部署方式补充#

不管用哪种生成器，部署到 GitHub Pages 有两种路径：

  • 分支部署：直接在仓库的 main 或 gh-pages 分支放构建产物，GitHub 自动托管
  • GitHub Actions 部署：通过 workflow 文件自动化构建和部署，灵活性更高（你目前用的就是这种方式）

使用 Hugo 搭建个人博客的完整过程总结#

整个流程可以概括为：本地用 Hugo 生成博客 → 推送到 GitHub 私有源码仓库 → GitHub Actions 自动构建 → 推送到公开的 Pages 仓库 → 通过域名访问。

一、环境准备#

  1. 安装 Git：前往 Git 官网下载 Windows 版本，默认安装即可
  2. 安装 Hugo：前往 Hugo Releases 页面下载 hugo_extended 版本（注意选 extended 版，支持 SCSS 编译），解压后将 hugo.exe 所在目录添加到系统环境变量 PATH 中
  3. 验证安装：打开 CMD 或 PowerShell，执行 hugo version，看到版本号输出即成功

二、创建 Hugo 站点#

hugo new site my-blog
cd my-blog
git init

执行后会生成标准目录结构：content/（文章）、themes/（主题）、static/（静态资源）、hugo.toml（配置文件）等。

三、添加主题#

Hugo 默认没有主题，必须手动添加。以 Git 子模块方式引入：

git submodule add <主题仓库地址> themes/<主题名>

然后在 hugo.toml 中指定主题：

theme = "主题文件夹名"

热门主题有 PaperMod、LoveIt、Stack、Ananke 等，可在 Hugo 主题库中按星标挑选。

四、写文章与本地预览#

# 创建文章
hugo new posts/my-first-post.md

# 编辑文章内容，注意将 draft: true 改为 draft: false

# 启动本地预览（支持热重载）
hugo server -D

浏览器访问 http://localhost:1313 即可查看效果。

五、GitHub 仓库配置#

需要创建两个仓库：

仓库用途可见性
源码仓库（如 my-blog）存放 Hugo 源文件（Markdown、主题、配置等）私有
Pages 仓库（<用户名>.github.io）存放构建后的静态文件，对外提供访问公开

Pages 仓库名称必须是 <GitHub用户名>.github.io，这样访问地址就是 https://<用户名>.github.io。

六、配置 GitHub Actions 自动部署#

在源码仓库中创建 .github/workflows/ 目录，编写 workflow 文件，核心流程是：

  1. 监听 main 分支的 push 事件
  2. 安装 Hugo
  3. 执行 hugo 命令构建静态文件
  4. 将构建产物推送到 Pages 仓库

部署时需要使用 Deploy Key 实现跨仓库推送：

  • 生成 SSH 密钥对：ssh-keygen -t ed25519
  • 公钥添加到 Pages 仓库的 Settings → Deploy keys（必须勾选 “Allow write access”）
  • 私钥添加到源码仓库的 Settings → Secrets → Actions，命名为 DEPLOY_KEY

七、踩坑记录#

在配置 Deploy Key 过程中遇到了几个典型问题：

  • Repository not found：Pages 仓库尚未创建，访问地址返回 404。解决方法是先创建 <用户名>.github.io 仓库
  • Permission denied to deploy key：Deploy Key 默认是只读的，必须手动勾选 “Allow write access” 才有推送权限
  • Key is already in use：同一个 SSH 公钥不能重复绑定到多个位置。解决方法是重新生成一对全新密钥，确保公钥和私钥配对正确

最终效果#

每次在本地写完文章后，只需：

git add .
git commit -m "新增文章"
git push

GitHub Actions 会自动完成构建和部署，几分钟后访问 https://<用户名>.github.io（或自定义域名）即可看到更新后的博客。整个过程完全免费，无需维护服务器。
