什么是上下文工程

2026年8月7日 · 1 分钟 · 94 字 · beyond

上下文工程（Context Engineering）是提示词工程（Prompt Engineering）的自然演进，核心是动态管理喂给 AI 的全部信息，让它在正确的时间拿到正确的信息，从而稳定输出预期结果。

通俗类比#

AI 研究者 Andrej Karpathy 有一个经典比喻：

LLM（大模型）= CPU，上下文窗口 = 内存（RAM），上下文工程 = 操作系统

CPU 再强，如果操作系统调度不好内存，程序照样崩。同理，模型再聪明，如果喂给它的信息乱七八糟、太多太少或时机不对，输出照样拉胯。上下文工程干的就是这个"操作系统"的活。

和 Prompt Engineering 的区别#

维度Prompt EngineeringContext Engineering
关注点单次输入怎么写好整个信息流怎么动态管理
适用场景单轮对话、简单任务多轮对话、复杂 Agent 任务
本质写好一段"指令"构建一个"信息流水线"
类比写一张便签设计整个图书馆的借阅系统

一句话总结：Prompt Engineering 是"怎么问"，Context Engineering 是"怎么管信息"。

为什么需要上下文工程？#

AI 模型有三个固有缺陷，单靠写好 Prompt 解决不了：

  • 无记忆：每次调用都是全新的，必须把所有相关信息重新塞进去
  • 上下文窗口有限：塞太多信息会互相"稀释"，模型反而抓不住重点（即"中间遗忘"问题）
  • 意图漂移：多轮对话越往后，AI 越容易"忘记"最初设定的规则

正如业界总结的：“大多数 Agent 的失败已经不是模型的失败，而是上下文的失败。”

核心方法论：“写、选、压、隔”#

这是上下文工程的四个关键操作：

写（Write）#

把暂时不用但未来可能需要的信息（中间结果、用户偏好、历史状态）写入外部存储，相当于给 AI 装一个"笔记本"。

选（Select）#

每次调用模型时，从所有可用信息源中精准筛选当前任务最相关的部分放入上下文窗口，去除噪声和冗余。

压（Compress）#

对长对话或冗长的工具返回结果进行摘要、修剪、去重，减少 Token 消耗。比如 Claude Code 就采用了递归摘要策略，在上下文窗口达到 95% 容量时自动压缩早期对话。

隔（Isolate）#

将复杂任务拆分为子任务，各自在独立的上下文中执行，避免信息互相干扰。多智能体场景中尤其重要。

一句话总结#

上下文工程 = 像策展人一样，从海量信息中精选出最合适的"料"，在正确的时机、以正确的格式喂给 AI，让它稳定产出你想要的结果。

它不是一个具体的工具或框架，而是一套设计 AI 系统信息流的思维方式和工程方法。随着 AI Agent 越来越复杂，上下文工程正在取代 Prompt Engineering 成为 AI 开发的核心技能。
